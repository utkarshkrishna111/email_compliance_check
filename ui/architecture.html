Section 01
System Overview

The Email Compliance AI Agent ingests bank email files (PDF / Excel), runs each email through a multi-stage LangGraph AI pipeline, and then performs cross-email pattern analysis to surface Quid Pro Quo arrangements and Circular Trading schemes that no single email can reveal.

▸ Intelligence / Scoring Layer
📊
scoring_engine.py
Computes priority score 0–100: Σ(category base_weights) × multi_category_bonus (if ≥2 cats) × high_confidence_bonus (if conf ≥ 0.8) → normalised. Maps score to band (CRITICAL/HIGH/MEDIUM/LOW) and alert level.

sender_risk.py
Aggregates a sender's full history from SQLite into a risk score 0–100: violation_rate×50 + avg_confidence×30 + severity_score×20. Produces risk bands CLEAN → HIGH_RISK. HIGH_RISK senders get +10% score boost.
Input: sender stats from SQLite · No LLM call

anomaly_detector.py
Z-score analysis of a sender's weekly email volume against their historical baseline (needs ≥3 weeks). Flags spikes > 2.0 σ. Appends anomaly note to LLM prompt and tags the scored finding.
Input: weekly volumes from SQLite · Z-score threshold: 2.0

Section 03
LangGraph Pipeline

Each email passes through a stateful LangGraph pipeline. Nodes share a typed ComplianceState dict. After the full batch completes, cross-pattern analysis runs once against the accumulated SQLite history.

01
detect_thread rule
thread_detector.py
Hashes normalised subject + sorted participant set → stable thread_id. Parses To/From fields for recipient list. Checks INTERNAL_DOMAIN to flag external emails. Writes: thread_id, recipients, is_external.
02
retrieve_history sql
history_store.py · sender_risk.py · anomaly_detector.py
Loads all prior findings for this thread from SQLite. Fetches sender stats → computes sender_risk (0–100, CLEAN→HIGH_RISK). Fetches weekly volume history → Z-score volume_anomaly check. Writes: thread_history, sender_risk, volume_anomaly.
03
build_context rule
context_builder.py
Summarises prior thread emails into a compact context block (saves ~62% tokens on long threads). Appends SENDER RISK PROFILE note if risk_score ≥ 40. Appends COMMUNICATION ANOMALY note if volume spike detected. Writes: extra_context.
04
compliance_agent llm 1
compliance_agent.py · compliance_matrix.yaml
Sends system prompt (all 7 categories + keywords, dynamically built from YAML) + extra_context + email to GPT-4o. Returns JSON: categories, intent, confidence, evidence, reasoning, is_compliant. System prompt auto-caches when ≥ 1024 tokens (Azure OpenAI prefix caching).
05
guardrail_check rule
guardrails.py — GuardrailValidator
Validates LLM output: required fields, confidence in [0,1], only valid category IDs (market_manipulation, bribery, secrecy, employee_ethics, change_in_communication, complaints, circular_trading), minimum evidence lines, minimum reasoning length, soft hallucination fingerprint check. Routes to verify (pass) or flag_review (fail).
PASS path
verify llm 2
Second GPT-4o call challenges the initial finding. Returns confirmed=true/false plus corrected_categories and corrected_confidence if wrong. Reduces false positives.
FAIL path
flag_review
Marks the finding as REVIEW_REQUIRED with alert_level=HIGH. Skips the second LLM call. Guardrail issues stored in finding for manual review.
06
score rule
scoring_engine.py · compliance_matrix.yaml
Σ(base_weight per category) × multi_category_bonus (if ≥2 cats, ×1.20) × high_confidence_bonus (if conf ≥ 0.8, ×1.15) → normalised to 0–100. Band: CRITICAL ≥80, HIGH ≥60, MEDIUM ≥40, LOW ≥0. HIGH_RISK senders get +10% boost. Volume anomaly flag is added to finding.
07
persist sql
history_store.py · storage.py
Writes to SQLite: historical_llm_response (full finding), recipient_network (sender→each recipient, flagged_count++), sender_weekly_volume (ISO week count). Upserts to ChromaDB for semantic search. Saves timestamped JSON to result/.
08
cross_pattern_analysis new
quid_pro_quo_detector.py · circular_trading_detector.py
Runs once after the entire batch (not per-email). Queries the now-populated SQLite DB. QPQ detector: SQL self-join to find reciprocal flagged pairs. Circular trading detector: builds recipient_network graph, runs DFS cycle detection. Results printed to console + returned via GET /api/patterns.
Section 04
Cross-Pattern Detection

Two detectors run after the batch completes, querying the history database to surface multi-email, multi-party schemes that individual email analysis cannot see.

🤝
Quid Pro Quo
Detects reciprocal-favour arrangements across separate email threads: Party A sends a flagged email to Party B, and Party B independently sends a flagged email to Party A — within a configurable time window.
  1. Query historical_llm_response for all non-compliant findings within days_window (default 30 days)
  2. Self-join: find pairs where email1.sender → email2.sender and email2.sender → email1.sender
  3. Filter: both emails must involve bribery, market_manipulation, or employee_ethics
  4. Verify actual addressing: sender2 must appear in recipients1 JSON array, and vice versa
  5. De-duplicate by canonical pair key; set severity based on average confidence
CRITICAL — avg conf ≥ 0.80
HIGH — avg conf < 0.80
in return for as a favor once you arrange our understanding scratch your back reciprocate mutual arrangement you take care of our deal stands quid pro quo
🔄
Circular Trading
Detects coordinated round-trip communication cycles in the recipient network: A → B → C → A where all edges carry market-manipulation or circular-trading flagged emails — the communication signature of wash trading.
  1. Query recipient_network for edges where flagged_count ≥ min_flagged (default 1)
  2. Verify each edge has a historical_llm_response record flagged for market_manipulation or circular_trading
  3. Build a directed adjacency graph: { sender: {recipients, …} }
  4. DFS cycle detection from each node in lexicographic order (start = minimum node avoids duplicates)
  5. Return unique canonical cycles of length 3–6 with severity and description
CRITICAL — cycle length 3–4
HIGH — cycle length 5–6
round trip wash trade mirror trade prearranged paint the tape synchronized buy you buy we sell inflate volume circular trade coordinate positions

ChromaDB — Semantic Vector Search
Each finding is embedded (subject + reasoning + evidence) and stored in the email_compliance collection with cosine similarity. Enables free-text similarity search: "find past violations similar to coordinated buy at 3pm". ChromaDB is optional — pipeline continues using only SQLite if not installed. Query via HistoryStore.semantic_search(query_text, n_results=5).

🌐
LangGraph Pipeline Path (graph.py)
When code calls build_graph() directly (e.g. from custom scripts), the pipeline runs through the full LangGraph StateGraph which additionally executes retrieve_history (sender risk + anomaly detection) and build_context (thread context substitution + risk/anomaly notes) before the LLM call. The run_cross_pattern_analysis(db_path) function in graph.py should be called after all emails are processed through the graph to obtain QPQ and Circular Trading alerts.
